# Disposable CI lifecycle qualification

This manual workflow is a dependent, **baseline-only** diagnostic proposal for
Story 2.8. It grants no candidate acceptance or loaded-backend identity credit.
The current 4.43.4/269 workflow/tool pins are deliberately unchanged. Published
4.43.4 and 4.43.5 cannot allocate in the required direct-only checkout because of
HXP020. A normally published corrected producer, qualified official archives,
coherent genuinely released Platform tuple and normal owner adoption are required
before dispatch. Preserve incoming root gitlinks; source preparation is not tuple
qualification. Never initialize nested dependencies or substitute source runtime.

The workflow must first be registered through normal main/source gates. After
registration, the operator checks all normal exact-source CI gates, dispatches
`.github/workflows/ci-lifecycle-qualification.yml` on that exact reviewed source,
and records repository, revision, run, attempt and qualification job identities.
The baseline job retains all 15 isolated projects, package consumers and required
`platform-package` real-service suite. Its failure prevents the qualification job.
Only the two dedicated pull-reader secrets are mapped; provider and publisher
credentials are not used.

| Input | Real observation |
| --- | --- |
| `matrix` | Passing and intentionally failing persistence suites; compatible same-job finite admission, explicitly disjoint negative context, completed-owner refusal; real owner-scoped metadata lock refusals and exact retry while an active peer remains functional; killed partial startup and exact recovery. |
| `cancel-startup` | Durable issued receipt, actual Starting AppHost and owned containers; only the issued AppHost is paused to expose the real startup window. |
| `cancel-execution` | Real gateway/Tenants/Memories and persisted EventStore assertions, native execution checkpoint and actual accepted 240-second hold. |

The dedicated fixture reuses `PartyEnvironmentTests`' existing real persistence
assertions. Missing descriptors or explicit controls fail, never skip. A passing
release of the active peer reruns the full real dependency, command, query and
exact-stream assertions. Only the initial call emits the canonical functional
observation with CreateNew; rechecks require that first file and never overwrite
or emit it again. Local filesystem controls reproduce duplicate-write refusal
and byte preservation without supplying native/hosted credit. The declared execution
limit is 300 seconds, fixture bound 240 seconds and production stop limit remains
90 seconds. Slow startup or a missed window fails explicitly; no retry-to-green
or timeout extension supplies credit.

Every owner role and exact receipt/launch-record location is journaled before
process creation. A test-controller child writes its actual PID, kernel birth and
process group, then waits at most 30 seconds at a pipe gate. Only a successful
durable parent bookkeeping save releases the unchanged public CLI command. Parent
interruption closes the gate without native allocation. The independent finalizer
recovers from the original intent and actual child record, including a constructor
that never returned. Missing process proof or a released child without a receipt
returns explicit unverified/non-success. A valid receipt still gets exact cleanup
when process/result metadata is malformed; no uncertain launch verifies cleanup.
Safe recovery observations remain outside the removed native workspaces.

For each cancellation dispatch, fetch **that run's**
`lifecycle-cancellation-ready` artifact before cancelling. Verify actual source,
repository/run/attempt/job, issued owner identity, phase and timestamps against
the live job and its wait step. Execution readiness must include the fixture's
real persistence marker and the unexpired original admission. Only the parent
operator may call GitHub's normal cancel API for that exact ready run. Save the
API request/response and actual UTC request time separately; the controller does
not cancel workflows. After the actual signal, the controller snapshots only the
current receipt/job-bound owner state before any resume or forwarded signal.
Startup credit requires actual Starting; execution credit requires Ready with
the same live native process and original active finite admission. Missing or
mismatched snapshots refuse credit after unconditional exact cleanup. A missing
readiness artifact, expired hold or already
terminal owner means no cancellation credit.

The wait step permits 120 seconds for actual SIGINT/SIGTERM. It saves observed
signals and any first terminal record before forwarding SIGINT to only the
receipt-bound process group it created. Signal observation is **not** the API
request time. The independent `always()` finalizer uses actual `job.status`,
resumes only the recorded owned AppHost, invokes exact public `down --run-id`,
and requires verified empty container/process/workspace/claim/discovery lists.
It also checks the controller-owned invocation has exited. Every sibling is
handled separately even when another fails.

Cancellation requires actual `cancelled`/`Cancelled` terminal status/outcome and
UTC time after the observed signal, original execution admission, durable
`ci-job-cancelled` withdrawal before its original expiry, then identical first
outcome/time and withdrawal/expiry through exact-owner retry. A pre-existing
product failure is preserved with its actual terminal time and observed signal;
it supplies no cancellation credit. Join its actual terminal time with the
parent's API receipt to establish whether it truly preceded cancellation.
Missing timing, changed first fields, unknown discovery or leftovers fails.

`TestResults/ci-lifecycle` retains classified public command results, tool-manifest
and mapping identities, real image reference/content IDs, receipt-issued owner
metadata, admission/withdrawal observations and safe producer reports outside
removed workspaces. Private descriptors, credentials and raw child stderr are
excluded. Artifact absence after cancellation remains an explicit evidence gap;
never infer cleanup from a cancelled job or a missing container list.

Local controls (no service allocation and no hosted credit):

python3 -B scripts/render-platform-declaration.py --check

Build the explicit LifecycleTests project only after supported pinned package
preparation, using Release/package imports. Both ordinary solution builds keep
this opt-in qualification project excluded. Record every genuine first outcome,
including dependency or public API refusals. No schema, production fault hook,
local retention policy, accepted pin or attached-suite execution is introduced.
