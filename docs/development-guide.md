## 1. Clone & submodules

Root-level shared Hexalith repositories live under `references/`. They are
**not** checked out in a fresh clone — initialise the root-repository submodules
needed by the baseline solution and local topology:

```bash
git clone https://github.com/Hexalith/Hexalith.Parties.git
cd Hexalith.Parties
git submodule update --init references/Hexalith.Platform references/Hexalith.Builds references/Hexalith.Commons references/Hexalith.EventStore references/Hexalith.FrontComposer references/Hexalith.PolymorphicSerializations references/Hexalith.Tenants references/Hexalith.Memories references/Hexalith.McpCli
# Do NOT use --recursive for the default local run (the build gate forbids nested-submodule init).
```

Memories is a required reference service. Its optional rich-search feature stays disabled in the Platform reference composition.

Plain builds retain package references. For local source development use the pinned module tool; it injects the selected direct roots, source flags and Debug configuration. Directory.Build.props does not probe siblings or choose a mode. Directory.Packages.props imports the direct Builds catalog default while respecting the tool-injected catalog authority.

## 2. Build

```bash
dotnet restore Hexalith.Parties.slnx
dotnet build Hexalith.Parties.slnx --configuration Release --no-restore
```

For release-blocker triage, prefer a sequential build so the first failing project is visible:

```bash
dotnet build Hexalith.Parties.slnx --configuration Release --no-restore -m:1 -p:NuGetAudit=false -p:MinVerVersionOverride=1.0.0
```

`TreatWarningsAsErrors=true` is solution-wide. A green build on a fresh clone (root-repository submodules under `references/` only, no warnings override) is the **build gate** — verify parity locally with:

```bash
bash scripts/check-no-warning-override.sh
```

See [build-gate.md](build-gate.md) for the policy and escape valves (narrow `<NoWarn>RuleId</NoWarn>` in the consuming csproj with an issue link — never a command-line `TreatWarningsAsErrors=false`).

## 3. Run locally (one command)

```bash
dotnet tool restore
dotnet tool run hexalith-module -- debug --manifest module/hexalith.module-manifest.v2.json
```

Wait for the tool to report all seven servers ready: `parties`, `eventstore`,
`tenants`, `tenants-api`, `memories`, `memories-access-telemetry-clock`, and
`memories-access-telemetry`. Infrastructure and sidecars are run-owned. Stop the
exact run with `dotnet tool run hexalith-module -- down --manifest module/hexalith.module-manifest.v2.json --run-id <run-id>`.

Set `HEXALITH_DAPR_HOME` to a prepared absolute isolated Dapr home as described in
the [pinned Platform prerequisites](../references/Hexalith.Platform/README.md#run-and-debug-a-technical-module).
An unset or unprepared home is refused before launch. Public traffic enters through
EventStore; service health endpoints remain `/ready`, `/health` and `/alive`.

## 4. Test

Use the **lane runner** (`scripts/test.ps1 -Lane <lane>`, default `unit`, Release) or run individual test projects by path. Do not use solution-level `dotnet test` for this repository; the `.slnx` is for restore/build only.

```bash
pwsh -NoProfile -File scripts/test.ps1 -Lane unit -Configuration Release
pwsh -NoProfile -File scripts/test.ps1 -Lane all -Configuration Release
dotnet test tests/Hexalith.Parties.Server.Tests/Hexalith.Parties.Server.Tests.csproj --configuration Release
```

| Lane | Scope |
|------|-------|
| `unit` | Contracts, Authentication, Client, Server, Projections, Security, AdminPortal, ConsumerPortal, Picker, Mcp, UI |
| `integration` | Hexalith.Parties.Tests + Sample.Tests |
| `topology` | Hexalith.Parties.IntegrationTests (full Aspire topology — needs Docker/DAPR; skips gracefully if absent) |
| `ci` | Hexalith.Parties.Ci.Tests (GitHub Actions/Zot publish contract validation) |
| `all` | all .NET test projects, executed one project at a time |
| `coverage` | currently blocked under Microsoft.Testing.Platform/xUnit v3 until an MTP-compatible coverage extension is configured |

### Fallback validation ladder

When the full solution build or `dotnet test` is environment-blocked, do not record validation as blocked until you have climbed this ladder. Each rung produces focused evidence; record which rung ran, which broader gate is still blocked, and the exact blocker.

1. **Focused lane / per-project run** — `scripts/test.ps1 -Lane <lane>` (or `dotnet test <projectPath>`). Never solution-level `dotnet test`.
2. **Direct xUnit v3 assembly filter** — build the target project, then run its built `.dll` directly with single-dash `-class`/`-method` (project-level `dotnet test --filter` silently runs zero tests under Microsoft.Testing.Platform; see below).
3. **Serialized `-m:1` build for release-blocker triage** — makes the first failing project visible (`dotnet build … -m:1 -p:NuGetAudit=false -p:MinVerVersionOverride=1.0.0`).
4. **Property pins for known environment blockers** — `-p:MinVerVersionOverride=1.0.0` (no git tags → version skew), `-p:NuGetAudit=false` (offline audit noise), and the pinned tool source mapping for diagnostic source builds; do not use handwritten source selectors to bypass missing mapped roots.
5. **Record the exact broad-gate blocker** — package NuGet-network (`api.nuget.org:443`), submodule gitlink drift, UI accessibility, or CI publish-contract validation — with the command, observed result, and required owner/environment. Never weaken a gate to hide a blocker.

The lane runner supports climbing rungs 1, 4, and 5 in one pass so a single run reports every failing project instead of stopping at the first:

```bash
# Continue past a failing project and print a PASS/FAIL summary for the whole lane (exit 1 if any failed)
pwsh -NoProfile -File scripts/test.ps1 -Lane all -ContinueOnFailure

# Emit an inspectable TRX per project (local parity with the CI shards)
pwsh -NoProfile -File scripts/test.ps1 -Lane all -ContinueOnFailure -ResultsDirectory TestResults

# Forward build/restore properties for a blocked lane (comma-separated; each becomes -p:<value>)
pwsh -NoProfile -File scripts/test.ps1 -Lane unit -Properties MinVerVersionOverride=1.0.0,NuGetAudit=false
```

Without `-ContinueOnFailure` the lane keeps its fail-fast behavior and stops at the first failing project. `-ResultsDirectory` accepts a repo-relative path.

xUnit v3 runs under Microsoft.Testing.Platform here. Project-level `dotnet test --filter` can silently run zero tests, so filter focused reruns by invoking the built test executable directly with xUnit v3 single-dash arguments:

```bash
dotnet build tests/Hexalith.Parties.Server.Tests/Hexalith.Parties.Server.Tests.csproj --configuration Release --no-restore -m:1 -p:NuGetAudit=false -p:MinVerVersionOverride=1.0.0
dotnet tests/Hexalith.Parties.Server.Tests/bin/Release/net10.0/Hexalith.Parties.Server.Tests.dll -class Fully.Qualified.TestClass
dotnet tests/Hexalith.Parties.Server.Tests/bin/Release/net10.0/Hexalith.Parties.Server.Tests.dll -method Fully.Qualified.TestClass.TestMethod
```

Package compatibility tests in `Hexalith.Parties.Client.Tests` and `Hexalith.Parties.Contracts.Tests` can require network access to NuGet repository signature metadata. A sandbox or CI environment that blocks `api.nuget.org:443` has not validated those package tests; rerun them in a network-enabled package-validation environment before release.

The UI accessibility workspace lives under `tests/e2e`:

```bash
cd tests/e2e
npm ci
npm run test:config
npm run typecheck
python3 ../Hexalith.Parties.UI.Tests/verify-restored-assets.py
npm run install:browsers
npm run test:a11y
```

The local Playwright server builds Debug assets with package dependencies and uses the explicit
`Test` environment with the accessibility fixture enabled. For CI parity, build
the UI in Release/package mode first, then run the browser lane with `CI=true`
from `tests/e2e` (Bash):

```bash
dotnet build ../../src/Hexalith.Parties.UI/Hexalith.Parties.UI.csproj --configuration Release -p:UseHexalithProjectReferences=false -p:UseNuGetDeps=true
CI=true BASE_URL=http://127.0.0.1:5072 PLAYWRIGHT_SKIP_WEBSERVER= npm run test:a11y
```

CI runs the prebuilt UI without restoring or rebuilding in Playwright. This
fixture does not require Docker, Dapr or Keycloak. The blocking `ui-a11y` job
uploads browser reports and failure diagnostics as `ui-a11y-results`; see
[CI documentation](ci.md#ci). The `all` PowerShell lane remains the .NET suite;
run the npm lane separately for browser checks.

**Frameworks:** xUnit v3 + Shouldly (assertions) + NSubstitute (mocking); bunit for Blazor components; Playwright + axe for the browser accessibility gate; `Aspire.Hosting.Testing` for the topology lane (it manages the real DAPR/Redis containers); YamlDotNet for manifest validation. Note: `Testcontainers` is in the package manifest but **not referenced by any test project** — don't reach for it. See [component-inventory.md](component-inventory.md) for per-project coverage.

## 5. Configuration & feature flags (runtime)

Read by the `parties` host (`appsettings*.json` / env, `__` nesting):

| Section / key | Purpose |
|---------------|---------|
| `Authentication:JwtBearer` | JWT validation (OIDC `Authority` or symmetric `SigningKey` ≥32 chars; `Issuer`, `Audience`) |
| `Tenants` | tenant integration (ServiceName, PubSubName, TopicName `system.tenants.events`, CommandApiAppId) |
| `EventStore:Projections` | SDK read-model options (`ReadModelStateStoreName`, `FreshnessAgingSeconds`, `FreshnessStaleSeconds`) bound by `PartySdkReadModelOptions` |
| `Parties:CryptoShredding:IsEnabled` | crypto-shredding feature (**default true**) — see GDPR note below |
| `Parties:Compliance:GdprFeaturesActive` | suppresses the MVP compliance warning (**default false**) |
| `Parties:MemoriesSearch` | rich search (Enabled, Endpoint, ApiToken, TenantId, CaseId, EnabledAxes) |
| `EventStore:DomainServices` | EventStore domain-service registration (AppId / identity for gateway routing) |

Read by the `parties-ui` host:

| Section / key | Purpose |
|---------------|---------|
| `Authentication:OpenIdConnect` | host-owned OIDC client configuration; browser receives only the server-side cookie |
| `Parties:BaseUrl` | EventStore gateway base URL for typed Parties clients |
| `EventStore:SignalR:HubUrl` | EventStore projection-change hub for live freshness |
| `Parties:Freshness:PollingIntervalSeconds` | polling fallback cadence when live freshness is unavailable |
| `PartiesAccessibilitySpecimen:Enabled` | Development/Test-only accessibility specimen routing |

> ⚠️ **GDPR toggles are independent.** `Parties:CryptoShredding:IsEnabled` (the feature) defaults **on**; `Parties:Compliance:GdprFeaturesActive` (the MVP warning) defaults **off**. The default key store is in-memory/dev-only, so do not store regulated EU personal data until a production KMS or secret-store-backed key provider is provisioned.

## 6. Conventions

- **C#**: `net10.0`, nullable enabled, implicit usings, file-scoped namespaces, `sealed record` for contracts. Warnings are errors.
- **Commands/events** are immutable records in `Contracts`; **never** add infra dependencies to `Contracts` (architectural fitness test enforces this).
- **Event contract evolves additively** — new optional fields and new event types only; existing fields are never removed/renamed (forward-compatible subscribers). See [event-handler-patterns.md](event-handler-patterns.md).
- **Privacy**: never log event payloads or PII; projection logs carry only projection name + counts. Mark personal-data properties with `[PersonalData]`.
- **Idempotency**: command handlers are state-driven (`DomainResult.NoOp`); subscribers must dedupe and return `200 OK` for everything.
- **Versioning**: MinVer from git tags (prefix `v`); pre-release default `preview.0`.

### Projection diagnostics

The seven `PartySdkProjectionFold` drop diagnostics formerly used event ID `0`.
DW-46 assigns distinct IDs and uses each generated method name as its event name:

| Generated event name (method) | Event ID |
|---|---|
| `NonJsonEventDropped` | 4802 |
| `UnknownEventTypeDropped` | 4803 |
| `AmbiguousEventTypeDropped` | 4804 |
| `PayloadDeserializationFailed` | 4805 |
| `RedactedEventDropped` | 4806 |
| `WholePayloadRedactedEventDropped` | 4807 |
| `NullPayloadEventDropped` | 4808 |

Update alerts and saved log filters that select these diagnostics by event ID
`0` to select the IDs or event names above. Existing message templates, fields,
and severity levels remain unchanged.

DW-47 assigns dedicated categories to per-event fold diagnostics (4802–4808):

| Handler path | Logger category |
|---|---|
| Detail live delivery, rebuild, and unresolved processing audit | `Hexalith.Parties.Projections.Handlers.PartyProcessingActivityFold` |
| Index live delivery and unresolved delivery failure | `Hexalith.Parties.Projections.Handlers.PartySdkProjectionFold` |
| Index shared rebuild summary (4801) | `Hexalith.Parties.Projections.Handlers.PartyIndexSdkProjectionHandler` |

Migrate category filters, saved queries, and alerts for per-event diagnostics
from the Detail or Index handler category to the assigned fold category above.
Keep filters for summary 4801 on the Index handler category. Shared Index
rebuilds retain bounded summaries; they do not emit per-event fold diagnostics.
Detail's second event walk stays silent, and optimistic retries do not duplicate
fold diagnostics within a delivery. Fully applied redeliveries stay silent.

The SDK host supplies `ILoggerFactory` through DI. When constructing the
host-private handlers manually, Detail's optional fourth argument is now
`ILoggerFactory`; existing three-argument construction remains valid. Index
retains its optional typed handler logger for summary 4801 and appends an
optional factory for fold diagnostics:

```csharp
var detail = new PartyDetailSdkProjectionHandler(store, batchStore, options, loggerFactory);
var index = new PartyIndexSdkProjectionHandler(store, options,
    logger: loggerFactory.CreateLogger<PartyIndexSdkProjectionHandler>(),
    loggerFactory: loggerFactory);
```

Omitting the factory disables optional fold logging without changing projection
results; Index never falls back to its typed handler logger for fold diagnostics.
Disabling a fold category likewise suppresses its diagnostics without changing
persisted output. Direct fold APIs continue to accept an optional `ILogger` and
retain that logger's category.

## Platform reference qualification

Use accepted tool 4.34.0 from an independent Parties checkout. Initialize only its
direct references, including Platform, Memories and McpCli. The tool selects the
seven-server dependency closure and emits a run ID, mapping and diagnostics.
Break in `MvpComplianceWarningMiddleware.InvokeAsync` on `/ready`; a disposable
edit to `MvpComplianceWarning.Message` must change the existing warning header.
Restore the edit, stop the exact run (`down --manifest module/hexalith.module-manifest.v2.json --run-id <run-id>`), and rerun clean.
Record full revisions, environment, active source/PDB paths, results and cleanup.
Owner review and upstream integration are required before qualification is complete.

Legacy AppHost, Aspire helpers, UI/MCP and sample hosts remain frozen for continuity
and owner tests. They do not supply Platform qualification evidence. The owner ACL
is authoritative: regenerate with `python3 scripts/render-platform-declaration.py`
and verify with `--check`. Security record keys and formats remain unchanged when
`Parties:Security:StateStoreName` binds a different Dapr component. Readiness still
gates on sidecar, state and enabled Tenants integration; pub/sub stays a degraded
health signal. Tenant subscriptions are declarative at `/tenants/events` on
`system.tenants.events` and rich Memories search remains disabled.

### Qualifying all local Dapr sidecars with mTLS

Use the [DW-77 qualification command and prerequisites](../tests/README.md#complete-local-mtls-qualification-dw-77)
to start the complete disposable test profile. Both optional profiles are enabled;
the ordinary health fixture keeps its default profile. Run serially because the
secure Dapr control plane uses fixed local names and loopback ports. The fixture
restores its environment and removes only resources it owns, including after
startup failure or cancellation. Credentials must stay out of captured evidence.

Qualification proves eight responsive credentialed sidecars, the existing
Parties-to-Tenants readiness invocation and authenticated tenant-event bootstrap.
Production subscription-handler access effects are inspected in process through
existing services; no public endpoint is added. Runtime deployment and end-to-end
command/projection qualification remain separate work.
