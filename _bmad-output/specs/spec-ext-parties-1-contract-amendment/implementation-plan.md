## Coordinated migration

1. **Ratify the proposal before adapters.** R1/R2/R7 approve exact schemas, Q5 mapping, F1 privacy/issuer semantics and legacy path. Resolve backend/authority/work/operational ownership R3–R9 before production provider/host tasks. Keep hardware work stopped. Approved clauses alone do not satisfy these gates.
2. **Build readers and refusal first.** Land shared V2 contracts, strict/mismatch rejection, parsers and validators in their owners; then Platform/Parties readers and codecs. Enroll no production provider yet. Run deterministic contract round-trips and old/new compatibility vectors. Version routes/event names/snapshot markers ensure already-installed old code cannot parse amended artifacts as strict.
3. **Inventory the installed cohort and all existing units.** Owners bind exact hosts/holders/packages/images/source/profile/config/plan/trust, copy classes, old writers and current authority. Preserve existing provisioned Party links. Classify each original as unchanged strict, authenticated migration candidate or unsupported. Unsupported/ambiguous entries block their scope; do not allocate replacement identities or extend E.
4. **Prepare a closed cutover.** Deny new admissions/use for the affected scope; fence old writer/worker/transport incarnations; drain or explicitly classify every released holder. Cancellation and a completed rollout do not prove holder retirement. Disable old v1 serving paths for amended units, including replay/rebuild/source/cleanup; a routing flag alone is insufficient. Unrelated qualified scopes may stay live only with demonstrated isolation.
5. **Migrate only with proof.** A still-live original may be decoded under current old authority, assigned a separate V2 compatibility attestation and independently segmented before E. Preserve original identity, policy, binding version/effective instant/E, source positions and old artifacts; record new copies/generations and reconcile all old ones under accepted deadlines. Do not rewrite old event bytes or pretend the strict receipt certified amended behavior. Already-expired entries cannot be decrypted just because destruction is pending; absent actor-free mapping keeps F1 unavailable. Migration needs explicit changed-guarantee acceptance for existing originals, not blanket grandfathering.
6. **Install one coherent target with serving closed.** Both actual hosts, Platform work/receipt/authority/observer, EventStore source/protection, Parties codecs/handlers/clients, downstream holders and all verifiers require the same exact profile. Missing/old participant fails readiness. Record actual runtime image IDs, package hashes, scope enrollment and trust; source labels/config digests alone do not establish installation.
7. **Accept complete replacement and qualify it.** Owners supply all nine register fields and the full immutable source/package/image/install/profile/configuration/plan/trust target and achievable date. Applying a changed contract without this acceptance makes the changed record Uncommitted; the proposal does not alter the old Committed record. Only the exact accepted owner command may qualify a Committed seam, under its independently authorized D03/D04 scopes and retained prerequisites. A real B15 pass path is required. Passing full installed Level 4 permits Available; Local/Readiness does not.
8. **Enable consumers only under their gates.** Agents/Conversations consuming execution remains blocked until relevant records are Available at the exact target. Preserve OQ-5.4-1 and the protection → secrets without host references → host composition → mutual cases order under their accepted prerequisites. Level 5/RQ-1 is the consuming launch gate and remains required; no circular demand to mark it passed before beginning the authorized owner qualification run.

## Rollback, version drift and incidents

Before any V2 write, rollback can restore the previous serving arrangement only for independently qualified unchanged strict units after current-authority reconciliation. After a V2 write/adoption, old binaries cannot serve amended originals. Roll back code only to a V2-capable exact target or keep the affected scope quarantined. Never lower epochs, rewrite assurance tokens, renew E, discard pending destruction or reset attempts to make an old target appear compatible. Cleanup/recovery continues under authorized current owners despite serving rollback.

A mixed writer/reader/cleanup/verifier rollout must fail closed. Inventory drift or a newly discovered copy after finalization creates an incident and current receipt invalidity; retain the original signed receipt and complete the same original destruction lineage. Deadlines and sticky breaches survive restart/outage/recovery. Owners must accept how an invalidation is delivered to every verifier before production use (R6/R9).

## Complete acceptance packet

The nine fields after stable ID are Owner, Repository, RequiredArtifact, TargetVersionOrCommit, TargetIntegrationDate, CompatibilityContractAndVerificationCommand, RequiredEvidenceLevel, AcceptedStatus and ConsumingStories. Include exact coordinated sources/packages/runtime image IDs, installations, trust and value-free configuration/plan hashes; actual environments/tenants/operator references, C01–C16 and holder inventory, authority outside restore cuts, D03/D04 scopes, F1 issuer/privacy policy and independent assertions. Missing fields are blockers; a digest of null bindings is not an installed target.

Extend the existing owner verifier rather than inventing an installed executable here. Its future accepted command must guard the clean exact owning checkouts and installed target before protected lookups/effects, reserve a fresh evidence directory, execute every required lane, reject skips/unrun/zero tests and retain every failure. Exact argv/cwd/tool hashes and integration date remain R10; no shell placeholder is offered as a qualifying command.
