# Proposed API and DTO schemas

These are proposed contract names and shapes for owner review, not implemented or published APIs. EventStore owns reusable transport/protection/source contracts, Platform owns custody runtime/lifecycle operations, and Parties owns domain identity/events and snapshot meaning. Authentication and operational trust/crypto bindings remain owner decisions; a proof reference below never authenticates itself.

## Encoding and validation

Wire properties use exact camelCase, UTF-8 JSON, explicit UTC RFC 3339 instants and named string enums. Required means present and non-null; optional fields appear only in the stated union branch. Reject duplicate properties including case aliases, unknown fields, numeric/unknown enums, invalid dates, overflow, empty IDs, mismatched scope and unexpected union branches. Use checked integers and preserve full timestamp precision; equality compares instants, not strings. Existing owner identifier rules remain authoritative; do not introduce GUID-only parsing or alter legacy Party IDs.

Propose a canonical digest preimage as an ordered JSON array of the declared fields, with integer numbers, invariant UTC timestamps at seven fractional digits, exact strings, explicit nulls and nested declared arrays. Canonical serializer emits no whitespace, fixed JSON escapes, invariant numbers and UTF-8; SHA-256 output is lowercase 64 hex. Hash test vectors must pin escaping, field order and offset normalization before implementation. This is a proposed encoding decision R1, not a backend/trust selection. Bind protected payloads with authenticated encryption and this exact header as AAD; actual approved algorithms/key/issuer/trust profiles remain R3/R5/R9.

Retain current EventStore retained-history byte/position/time caps as upper limits; v2 expands no cap implicitly. Bounded inventory/receipt pages use authenticated manifest digest/count plus page indexes, reject duplicate/missing pages and require complete coverage before finalization. Page-level proof is not whole-inventory proof. Operational payload/page quotas must be bound in the accepted profile (R4/R9); null limits reject startup/admission.

`HistoryAdmissionResultV2` is a union: Admitted or AlreadyAdmitted requires evidence; Pending carries original reservation/operation refs with no usable evidence; Conflict, Denied, Unavailable, UnsupportedAssurance or AssuranceContractMismatch carries only a safe code. Original lookup is separate and read-only: exact key or exact existing evidence/operation plus authenticated scope; outcome OriginalFound returns immutable original, Pending/NotFound/Conflict/Denied/Unavailable never allocates a unit or mints absence evidence.

Propose `IIdentityHistoryCustodyV2` beside the unchanged strict interface:

| Method | Input → output and responsibility |
| --- | --- |
| AdmitAsync | HistoryAdmissionRequestV2 → HistoryAdmissionResultV2; reserve and reconcile exact original before key allocation. |
| LookupOriginalAsync | Exact original key or evidence/operation reference, assurance and authorized scope → original lookup union; no effects. |
| AuthorizeUseAsync | HistoryUseRequestV2 → HistoryUseDecisionV2; current participant proof, not cached CanRead Boolean. |
| ProtectEventAsync | HistoryProtectionContextV2 + owned JSON bytes → SealedHistorySegmentV2; registered copy obligation precedes release/append. |
| UnprotectEventAsync | Exact scope + sealed segment + use context → ReadableHistorySegmentV2 or typed safe refusal; current checks before and after remote work. |
| ProtectSnapshotAsync | Domain-produced segment mapping + profile-protected payload → HistorySnapshotSegmentsV2; independent original deadlines and no expired re-encryption. |
| UnprotectSnapshotAsync | Exact scope + HistorySnapshotSegmentsV2 + use context → bounded owned live segments plus authenticated expired-segment references; missing continuation proof denies whole semantic reconstruction. |
| RequestDestructionAsync | Exact original immutable unit + original destructionOperationId → LifecycleResultV2; not a Boolean and not a receipt merely because a request was accepted. |
| LookupDestructionAsync | Same exact original tuple → LifecycleResultV2 with optional original final receipt; read-only, never restarts deletion. |

All methods take CancellationToken. Each provider wait is bounded at 5 seconds; enclosing source/query limits remain. Observe and dispose late results, clear owned bytes and retain unknown destructive effects as pending work. A successful Unprotect return is not permission for a later consumer handoff; the receiving process is a separate holder.

`LifecycleResultV2` is a closed union: Observed requires LifecycleObservationV2 and optional exact original receipt; Unavailable, Denied, Conflict, UnsupportedAssurance or AssuranceContractMismatch carries only a safe code and authorized original-request reference, with no invented current observation. Unavailable observation leaves durable work Pending; it never proves absence. A RootKey holder is an incident to inventory, not permission to export a root.

Platform proposes a separate `IdentityHistoryCleanupV2.ProcessAsync` returning LifecycleResultV2. Pending is not completed; DurableCopiesDestroyed is not final; VerifiedCompleteWithinApprovedScope requires the authenticated original receipt and fresh authoritative expiry denial. Existing ProcessAsync and ProviderConfirmedDestroyed remain strict. Provider flags and DTO values cannot substitute for installed profile qualification.

## Final receipt and recovery semantics

Propose `IdentityHistoryDestructionReceiptV2` with required fields:

| Field group | Exact content |
| --- | --- |
| Identity | assurance; receiptId; unit: OriginalUnitV2; destructionOperationId; originalRequestDigest. |
| Guarantee | guaranteeScope=amended-service-expiry-bounded-durable-destruction; approvedClauseDigest; operationalAcceptanceRef; metadataRetentionPolicyRef; holderState. No legacy strict flags. |
| Authority | terminalAuthorityEpoch; terminalLifecycleRevision; terminalFenceRevision; observerEvidenceRefs; authentication: {proofProfileRef: ref, issuerRef: ref, keyVersion: string, proofBytes: base64}. Proof covers the canonical receipt body excluding authentication; encode the body in the field-group order shown here. Trust profiles independently verify the issuer/key and canonical bytes. These attest actual terminal facts; a fresh current wrapper is needed on later lookup. |
| Inventory | frozenInventoryGeneration; frozenInventoryDigest; registrationClosureEvidenceRef; generationRefs; copyOutcomes: complete [CopyOutcomeV2] or complete authenticated paged manifest; residualHolders: [HolderResidualV2]. |
| Times | expiresAt; onlineDueAt; durableDueAt; onlineCompletedAt; durableCompletedAt; scopedCompletedAt; evidenceDueAt=min(scopedCompletedAt+900 s,E+2,592,900 s) when destruction is on time; verifiedAt; receiptCommittedAt. Late destruction uses actual completion+900 s and retains its original missed-deadline breach. Do not substitute receipt/read/observation time for actual completion. |
| Final check | deniedReadDecisionRef; deniedReadReason=ServiceExpired; finalizationState=VerifiedCompleteWithinApprovedScope; limitations: explicit inaccessible-memory/prior-recipient scope; breachJournalRef; knownBreachIds. |

Reserve the stable destruction operation with original admission (or an explicit exact legacy migration reservation). Physical destruction substeps may have stable per-copy IDs under it; retries never create a new original or reset E/inventory lineage. An irreversible terminal receipt is byte-immutable. Commit by current fenced compare-and-set; concurrent finalizers recover the same original bytes. Lost acknowledgement returns the same receipt via read-only lookup, not a new “completed” timestamp. If an attempted request changes the digest at the same operation ID, return Conflict and preserve the original.

Keep an append-only publication/breach journal beside that original: final evidence publication time and independent acknowledgement, missed-evidence facts, newly discovered copies, invalidity and subsequent holder retirement can be learned after the core receipt is committed. An acknowledgement loss alone does not prove non-publication; independently resolve the original. A current `DestructionLookupResultV2` wraps original receipt bytes/digest, current authority, current breach/invalidity journal head and current holder observations. It never rewrites the receipt or suppresses later incidents. A known invalid scope claim cannot verify as currently complete even if its original signed receipt exists.

The deadline check uses actual milestone times and independently verifiable durable evidence availability, not the first successful client lookup. No evidence reference extends retention indefinitely: R6 must define minimization, access, erasure and verification-window policy, including how long lookup is promised. Beyond an explicitly approved retention window return a typed EvidenceNoLongerRetained, never a fabricated receipt or renewed operation.

## Parties identity contract V2

Keep gateway-owned command/query transport; add no direct public Parties endpoint. Propose wire query names ResolvePartyIdentityV2 and ResolveHumanActorBindingAtV2, and new establish/rebind/revoke V2 event/command names where the embedded evidence shape changes. Existing provisioned IDs/Organization behavior and create-only exact retries remain unchanged; use a distinct versioned result/handler when conveying V2 assurance. IPartiesIdentityClientV2 retains explicit immutable per-call tenant scope.

`HumanActorBindingEvidenceV2` preserves tenantId, partyId, actorId, bindingVersion, actorRevision, validFrom, exclusive nullable validUntil, sourceId and provenanceId; replaces custody with HistoryAdmissionEvidenceV2; adds currentUseDecision and bindingSourcePosition. A live segment can include these protected fields only while permitted under its original unit. Propose AuthorityPositionV2 {sourceId: string, revision: string, position?: nonnegative int64}. Current identity V2 evidence retains classification, active/restricted/erasing-or-erased state, sourcePosition, observedAt/observationId and humanBinding, and adds authorityPositions: [AuthorityPositionV2] covering every Party/source/actor authority actually used. Do not collapse independent positions into one invented revision.

`HumanActorBindingResultV2` retains outcome, identityContractVersion=2, tenantId, partyId, actionAt, sourcePosition, bindingSourcePosition, observationId and nullable evidence; adds assurance and nullable F1 proof. Resolved requires the exact unique interval, recorded actor/version matching when supplied, complete source and current permission. Closed typed outcomes include Gap, Ambiguous, Mismatch, Revoked, Expired, Unavailable, UnsupportedAssurance and AssuranceContractMismatch; uncertainty is never authoritative absence. Current erasure/restriction immediately removes eligibility even while authorized historical attribution remains within E.

Unauthorized/cross-tenant callers receive the existing non-disclosing public failure shape with no foreign IDs/counts/receipt references. Authorized service owners retain safe typed distinctions. New mismatch reasons must map through the existing gateway failure mechanism; proposed HTTP 503 for assurance/authority unavailability, 409 for authorized immutable-intent conflicts, and the current generic unauthorized/absent mapping for inaccessible targets require R1 ratification. Never map to success, current-binding fallback, NoEligibleApprover or proposal abandonment.

## F1 V2: complete service-expiry continuity while destruction is pending

The strict ExpiredIdentityHistoryCertificate remains terminal destruction proof. Propose distinct `ServiceExpiredHistorySegmentProofV2` and `RetainedIdentityHistoryStreamV2`. They certify exclusion from service, not physical erasure. Their producer is the EventStore authoritative source reader plus independent current expiry authority; Parties verifies domain binding semantics. Platform supplies lifecycle evidence, not a Parties-specific fold.

| Proposed field | Contract |
| --- | --- |
| Top-level stream | assurance; exact HistoryScopeV2; purpose; head; observationId; observedAt; exclusive validUntil; sourceAuthorityRevision; currentAuthority; issuerProofRef; entries: ordered [SourcePartitionEntryV2]. All positions 1..head exactly once; no partial response. |
| SourcePartitionEntryV2 | sourceSequence; disposition=ProfileExcluded or History; ProfileExcluded carries no payload/type; History carries eventTypeName, payloadVersion, authenticated sealedManifestDigest and segments. Every committed manifest segment occurs exactly once. |
| Live segment | sourceSegmentId; disposition=Readable; sealedSegmentDigest; original-unit evidence; ReadableHistorySegmentV2. Live successor actor/version/interval and original positions are reproducible without expired/profile decrypt. |
| Expired segment | sourceSegmentId; disposition=ServiceExpired; sealedSegmentDigest; expiryProofRef; destructionState=PendingDestruction, DurableCopiesDestroyed or VerifiedCompleteWithinApprovedScope; finalReceiptRef only if one exists. No actor, provenance, logicalId, issuer/subject or plaintext-derived/recoverable identity hash. |
| Expiry proof | schema/assurance, exact source identity/position/manifest/segment ciphertext digest, current terminal service-expiry authority/epoch/fence, observedAt and exclusive validUntil, issuerProofRef. The protected issuer resolves immutable original E; caller cannot replace it. Export no expired binding payload/actor interval. Opaque proof references remain purpose-limited metadata. |
| Domain continuity summary | skippedBindingVersionRanges: disjoint half-open positive integer version ranges; liveSuccessors: [{bindingVersion,validFrom,validUntil?,openingSourcePosition,closingSourcePosition?}]. No expired actor or logical reference; summary must exactly match source segment partition and independently authenticated original transition/version metadata. It grants no actor authority. |

Partition membership and version transitions must be authenticated from the committed original segment manifest/version metadata established while the original was live. No expired predecessor is decrypted to generate or validate F1. Reject gaps, duplicate/overlapping source positions or segments, missing manifest members, overlaps in binding intervals/versions, tampering, stale/foreign epoch, head drift during observation, expired certificates, revoked issuer or a summary inconsistent with the live successor. Certificate validity is capped by current source/actor authority and each returned live unit's E; re-issuance never extends a binding's E.

A rebind source entry can hold a predecessor-close segment and successor-open segment under different original units. A snapshot maps every duplicate to those same units. This is why v2 partitioning must be per authenticated segment as well as per source position. The proposed v2 domain fold accepts only a proven unique live successor interval; querying an expired action returns Expired, never a reconstructed actor. Raw successor key survival alone is insufficient.

Legacy monolithic events do not acquire a safe split or actor-free manifest by assertion. An owner-approved pre-E migration may authenticate/decrypt a still-live original, append a migration attestation and split copies without altering old source bytes/positions/IDs/E, while inventorying both formats. If a legacy entry already expired and lacks a qualified actor-free source/version mapping, keep continuity unavailable; do not read it during the destruction window or infer the actor/version from current state. R2/R7 must approve legacy compatibility and F1 issuer/retention/erasure/rotation before production admission.
